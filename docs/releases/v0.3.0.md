# omnidevx v0.3.0 Release Notes

**Release Date:** 2026-10-07

## Overview

`omnidevx` v0.3.0 adds session recovery to the CLI. When you have many
Claude Code and Codex CLI sessions open across terminals, a reboot or a long
week leaves you unable to tell which was which. `omnidevx sessions` lists
them with their state and a title you can recognize, and resumes the one you
pick in the directory it started in.

The telemetry side is unchanged: `omnidevx collect` still records metadata
only. The session commands are the one place that reads titles and prompts,
and that text stays local. See the [Sessions guide](../guides/sessions.md).

## Highlights

- **List** — `omnidevx sessions` shows sessions newest first with the time of
  your last prompt separate from the time of the last agent activity, plus a
  state and a title. Filter by directory, harness, state, or recency.
- **Show** — `omnidevx sessions show <id>` prints the directory, branch,
  timestamps, recent prompts, and the resume command.
- **Resume** — `omnidevx sessions resume <id>` runs the agent's own resume
  command from the original directory. It refuses a session that appears to
  be running unless you pass `--force`, and stops if the directory no longer
  exists. `--print` shows the command instead of running it.
- **Privacy** — titles and prompts are read locally on demand and never
  written to the event store. `--no-content` omits prompt-derived text.

## Also in this release

- The CLI is built on Cobra; `collect` and `version` behave as before.
- `omnidevx version` now reports the real build version instead of a fixed
  `v0.1.0`.
- Session types and the catalog are re-exported from the top-level package
  for library users.

## Current limits

- Claude Code and Codex CLI sessions only. Kiro CLI is not listed.
- A Codex session you started fresh and still have open shows as `unknown`,
  because Codex records no live-process file. It shows `running` only when
  resumed with `codex resume <id>`.
- On Windows, no Claude Code session is reported as `running`, because the
  process start time cannot be verified. Check for an open window before
  resuming.
- The list shows a session's title and prompts, not yet which repositories or
  files it touched.

## Installation

```bash
go install github.com/plexusone/omnidevx/cmd/omnidevx@v0.3.0
```

Or as a library:

```bash
go get github.com/plexusone/omnidevx@v0.3.0
```

Requires Go 1.26+.

## Usage

```bash
omnidevx sessions --cwd . --since 7d
omnidevx sessions show 3f9a
omnidevx sessions resume 3f9a
```
